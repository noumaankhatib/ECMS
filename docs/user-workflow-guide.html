ECMS User Workflow Guide

Every screen, every field, with the exact value to type

Engineering Consultancy Management System (Kashif)
Version 1.0 · October 2026

How to read this guide

  • Each stage is one screen. Do the stages in order the first time.
  • Every field has a meaning, whether it is required (*), and an example value.
  • One running story is used throughout, so the example in one stage feeds the next.
  • Green boxes show the state after you save. Orange boxes are traps.

1.2 Roles

A user's role says what kind of work they do. Where they can do it comes from project membership: a Project Manager, Planning, Supervision or Document Controller user only sees projects they have been added to.

2.2 Wilayats  /wilayats

What it is. The list of wilayats offered on the property form. Picking from it keeps spelling identical everywhere, which makes searching and duplicate detection (plot number plus wilayat) reliable.

The Wilayats screen. The Villages recorded column fills in as properties are saved; you never type villages here.

FieldReq.Meaning and rulesExample
Name*The wilayat exactly as it should always be spelled. Unique. Up to 100 characters.Seeb
OrderPosition in the drop-down. Lower comes first.1

A new system comes pre-loaded with 62 wilayats across all governorates (Muscat, Muttrah, Bawshar, Seeb, Al Amerat, Quriyat, Salalah, Sohar, Nizwa, Sur and so on). For the story nothing needs adding: Seeb is already there. Add a name only if one is missing, or if your office spells one differently. Edit changes Name or Order; Retire hides it from new forms but properties that already use it are unaffected.

Trap. The pre-loaded spellings are only a starting point (for example Seeb, Quriyat). Check them against the spelling your office uses and rename before properties are entered, because properties keep the spelling they were saved with. A wilayat that is not on the list can still be typed on the property form, but it saves as typed and the form says "Ask an administrator to add it under Setup → Wilayats." Villages need no setup: they are suggested from villages already recorded under that wilayat.

3.1 Duplicate warning

On Save the system looks for the same CR number or Civil ID (a hard stop) or a similar name or the same phone (a warning only). If it finds a match you may open the existing client instead. Only a Director or System Administrator can override a hard stop, and they must give a reason of at least 5 characters, which is stored in the audit trail.

Revision moves: Submit and Start review (drawing:create), then Approve, Reject or Return for revision (drawing:approve: Director, System Administrator). The person who uploaded a revision cannot approve it; someone else must. They may still reject or return their own. A file must be uploaded with the revision; it cannot be added later and a revision without one cannot be approved. A revision with no file that you do not want must be Rejected or Returned for revision: while it sits under review it blocks completing the supervision workstream. Approved revisions never change. To change a drawing, upload the next revision (P2).

10. Complete and close a project

10.1 Complete each workstream

On the project page, Workstreams table: Start (Not started → In progress), then Complete. Complete is disabled until the list below it shows everything met.

WorkstreamMust be true
PlanningNo submission still in progress (draft, submitted, under review, returned or halted). Every milestone reached. Every activity done.
SupervisionNo open supervision issue. No drawing revision awaiting a decision. No modification awaiting a decision.

10.2 Mark the project complete

Press Mark complete once every workstream is Completed. The "Before marking complete" list shows "N of M conditions met", with a Go there link for each gap. The actual end date is recorded.

Director override. A Director or System Administrator may open Complete anyway…, type a Reason for overriding (5 to 500 characters, for example Client took over remaining snagging directly) and confirm. The reason and the unmet conditions are written to the audit trail.

10.3 Handover checklist, then Close

When the status is Completed the Handover card appears. Press Mark done beside each item. Ticks are one-way.

ItemMeaning
Final inspection doneFinal site inspection completed.
Authority completion documents receivedCompletion certificate or equivalent.
Mandatory tests receivedTest reports in hand.
As-built drawings receivedFinal as-built set.
Warranties receivedWarranty documents.
Final report issuedReport delivered to the client.

Close also needs no open issues and no missing required documents (stage 2.5). When all are clear the Close button turns on. The project manager (project:close) confirms "Closed is final".

After close: status Closed. Nothing in the project can be changed again: no new submissions, drawings, documents, issues or team changes.
No override for Close. If it is disabled: "Close all issues, upload every required document and complete the handover checklist first."

11. Admin tools after go-live  /admin/data

For System Administrators only (admin:data). Use only to remove records entered by mistake.

  1. Pick a tab: Clients, Properties, Projects or Proposals. Search to find the record (archived ones are included) and press View impact.
  2. The impact tree shows everything linked to it, all pre-selected. Untick what you want to keep.
  3. Archive selected hides records (only for clients, contacts, properties, activities, milestones, documents).
  4. Hard delete selected is permanent. A window asks you to type the root record's exact name, for example Salim Hamad Said Al Balushi, before the delete button turns on.
Hard delete cannot be undone. Check the impact tree twice. Records that belong to a closed project are still removable here, so be certain.
